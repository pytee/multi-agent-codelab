Step 1

Building a Multi-Agent System

5 minutes
ADKMulti-Agent PythonCloud RunVertex AI

Real-world problems are complex. While a single monolithic LLM agent might seem like the simplest solution, it quickly becomes unwieldy. A better approach is to decompose tasks into specialized, focused agents — each doing one thing well.

💡
Key Insight: Specialized agents are easier to evaluate, debug, and improve independently. You can update one without affecting the entire pipeline.

What You'll Build

A Course Creation System — a pipeline of four specialized agents:

Course Creation Pipeline Architecture
🎯 OrchestratorPort 8004
🔍 ResearcherPort 8001
→
⚖ JudgePort 8002
→
✎ Content BuilderPort 8003
AgentResponsibilityKey Feature
ResearcherSearches the web for topic infoGoogle Search tool
JudgeEvaluates research quality (pass/fail)Pydantic structured output
Content BuilderCreates the final course materialMarkdown formatting
OrchestratorManages the overall workflow loopA2A protocol

What You'll Learn

  • How to build focused, single-purpose agents with ADK
  • How to implement quality control loops using LoopAgent and SequentialAgent
  • How to connect agents via the Agent-to-Agent (A2A) protocol over HTTP
  • How to deploy a distributed multi-agent system to Cloud Run

Prerequisites

  • Basic Python knowledge
  • A Google Cloud project with billing enabled
  • Familiarity with terminal / command-line tools

Step 3

The Researcher Agent

10 minutes

The Researcher agent's sole job is to search the web and compile information about a topic. By keeping it focused, it becomes easy to test and improve independently.

Creating the Agent

Open agents/researcher/agent.py. The starter file already has the imports and MODEL constant — add the agent definition below the TODO comment:

from google.adk.agents import Agent
from google.adk.tools.google_search_tool import google_search


MODEL = "gemini-2.5-pro"

# Define the Researcher Agent
researcher = Agent(
    name="researcher",
    model=MODEL,
    description="Gathers information on a topic using Google Search.",
    instruction="""
    You are an expert researcher. Your goal is to find comprehensive and accurate information on the user's topic.
    Use the `google_search` tool to find relevant information.
    Summarize your findings clearly.
    If you receive feedback that your research is insufficient, use the feedback to refine your next search.
    """,
    tools=[google_search],
)

root_agent = researcher
🔮
Design principle: The agent has exactly one tool (google_search) and one clear purpose. This makes it predictable, testable, and replaceable.

How It Works

  • The Agent class wraps a Gemini model with instructions and tools
  • google_search is a built-in ADK tool that queries Google Search
  • The model decides when and how to use the tool based on the prompt

Step 4

The Judge Agent

10 minutes

The Judge evaluates whether the research meets quality standards. It uses a structured output schema to enforce consistent pass/fail decisions.

Defining the Schema and Agent

Open agents/judge/agent.py and add the schema and agent definition below the TODOs:

from typing import Literal
from google.adk.agents import Agent
from google.adk.apps.app import App
from pydantic import BaseModel, Field


MODEL = "gemini-2.5-pro"

# 1. Define the Schema
class JudgeFeedback(BaseModel):
    """Structured feedback from the Judge agent."""
    status: Literal["pass", "fail"] = Field(
        description="Whether the research is sufficient ('pass') or needs more work ('fail')."
    )
    feedback: str = Field(
        description="Detailed feedback on what is missing. If 'pass', a brief confirmation."
    )

# 2. Define the Agent
judge = Agent(
    name="judge",
    model=MODEL,
    description="Evaluates research findings for completeness and accuracy.",
    instruction="""
    You are a strict editor.
    Evaluate the 'research_findings' against the user's original request.
    If the findings are missing key info, return status='fail'.
    If they are comprehensive, return status='pass'.
    """,
    output_schema=JudgeFeedback,
    # Disallow delegation because it should only output the schema
    disallow_transfer_to_parent=True,
    disallow_transfer_to_peers=True,
)

root_agent = judge
💡
disallow_transfer_to_parent and disallow_transfer_to_peers prevent the Judge from delegating, ensuring it only emits the JudgeFeedback schema.

Why Structured Output?

  • Forces the LLM to return valid JSON matching the schema
  • The orchestrator can reliably parse status and feedback
  • No string parsing or regex needed downstream
  • The schema acts as a contract between agents

The Content Builder Agent

8 minutes

The Content Builder transforms approved research into a well-structured, engaging course. It only runs after the Judge gives a "pass."

Creating the Agent

Open agents/content_builder/agent.py and add the agent definition:

from google.adk.agents import Agent


MODEL = "gemini-2.5-pro"

content_builder = Agent(
    name="content_builder",
    model=MODEL,
    description="Transforms research findings into a structured course.",
    instruction="""
    You are an expert course creator.
    Take the approved 'research_findings' and transform them into a well-structured, engaging course module.

    **Formatting Rules:**
    1. Start with a main title using a single `#` (H1).
    2. Use `##` (H2) for main section headings.
    3. Use bullet points and clear paragraphs.
    4. Maintain a professional but engaging tone.

    Ensure the content directly addresses the user's original request.
    """,
)
root_agent = content_builder
🔮
Notice the Content Builder has no tools — it only needs its knowledge and the research passed to it. Simpler agents are more predictable.

Step 7

The Orchestrator & A2A Protocol

12 minutes

The Orchestrator coordinates the other agents over HTTP using the Agent-to-Agent (A2A) protocol. Each sub-agent runs as an independent microservice.

Connecting to Remote Agents

Open agents/orchestrator/agent.py. The starter file already imports BaseAgent, LoopAgent, SequentialAgent, RemoteA2aAgent, Event, EventActions, InvocationContext, CallbackContext, and create_authenticated_client, and defines the create_save_output_callback helper. Replace the remote-agent TODO with:

# --- Remote Agents ---

# Connect to the Researcher (Localhost port 8001)
researcher_url = os.environ.get("RESEARCHER_AGENT_CARD_URL", "http://localhost:8001/a2a/agent/.well-known/agent-card.json")
researcher = RemoteA2aAgent(
    name="researcher",
    agent_card=researcher_url,
    description="Gathers information using Google Search.",
    # IMPORTANT: Save the output to state for the Judge to see
    after_agent_callback=create_save_output_callback("research_findings"),
    # IMPORTANT: Use authenticated client for communication
    httpx_client=create_authenticated_client(researcher_url)
)

# Connect to the Judge (Localhost port 8002)
judge_url = os.environ.get("JUDGE_AGENT_CARD_URL", "http://localhost:8002/a2a/agent/.well-known/agent-card.json")
judge = RemoteA2aAgent(
    name="judge",
    agent_card=judge_url,
    description="Evaluates research.",
    after_agent_callback=create_save_output_callback("judge_feedback"),
    httpx_client=create_authenticated_client(judge_url)
)

# Content Builder (Localhost port 8003)
content_builder_url = os.environ.get("CONTENT_BUILDER_AGENT_CARD_URL", "http://localhost:8003/a2a/agent/.well-known/agent-card.json")
content_builder = RemoteA2aAgent(
    name="content_builder",
    agent_card=content_builder_url,
    description="Builds the course.",
    httpx_client=create_authenticated_client(content_builder_url)
)

The A2A Protocol

Each agent exposes an agent card — a JSON endpoint describing its capabilities. RemoteA2aAgent reads this card to discover how to communicate with the service.

💡
This is the same pattern as microservices: each agent is independently deployable, scalable, and replaceable. The orchestrator only needs the URL.

Step 8

Escalation Checker

8 minutes

The Escalation Checker is a custom BaseAgent that uses Python logic — not an LLM — to inspect the Judge's output and decide whether to continue the loop or break out.

Custom BaseAgent

In agents/orchestrator/agent.py, replace the Escalation Checker TODO with:

# --- Escalation Checker ---

class EscalationChecker(BaseAgent):
    """Checks the judge's feedback and escalates (breaks the loop) if it passed."""

    async def _run_async_impl(
        self, ctx: InvocationContext
    ) -> AsyncGenerator[Event, None]:
        # Retrieve the feedback saved by the Judge
        feedback = ctx.session.state.get("judge_feedback")
        print(f"[EscalationChecker] Feedback: {feedback}")

        # Check for 'pass' status
        is_pass = False
        if isinstance(feedback, dict) and feedback.get("status") == "pass":
            is_pass = True
        # Handle string fallback if JSON parsing failed
        elif isinstance(feedback, str) and '"status": "pass"' in feedback:
            is_pass = True

        if is_pass:
            # 'escalate=True' tells the parent LoopAgent to stop looping
            yield Event(author=self.name, actions=EventActions(escalate=True))
        else:
            # Continue the loop
            yield Event(author=self.name)

escalation_checker = EscalationChecker(name="escalation_checker")
🔮
Not every "agent" needs an LLM! For deterministic logic like parsing JSON, a custom BaseAgent is faster, cheaper, and more reliable than using a model.

Step 9

The Research Loop

8 minutes

Compose the Researcher, Judge, and EscalationChecker into a LoopAgent — a while-loop that retries until quality is approved.

Composing the Loop

In agents/orchestrator/agent.py, replace the Research Loop TODO with:

# --- Orchestration ---

research_loop = LoopAgent(
    name="research_loop",
    description="Iteratively researches and judges until quality standards are met.",
    sub_agents=[researcher, judge, escalation_checker],
    max_iterations=3,
)

How the Loop Works

  1. Researcher searches and returns research content
  2. Judge evaluates and returns {"status": "pass"/"fail", "feedback": "..."}
  3. EscalationChecker reads the status:
    • pass → escalate=True → loop exits
    • fail → feedback passed back to Researcher → loop repeats
⚠
Always set max_iterations to prevent infinite loops if the Judge keeps failing. A value of 3–5 is typical.

Step 10

The Final Pipeline

6 minutes

Chain the research_loop and content_builder together using a SequentialAgent.

Assembling the Pipeline

root_agent = SequentialAgent(
    name="course_creation_pipeline",
    description="A pipeline that researches a topic and then builds a course from it.",
    sub_agents=[research_loop, content_builder],
)

Agent Hierarchy

SequentialAgent (course_creation_pipeline)
├── LoopAgent (research_loop)         [runs until pass]
│   ├── RemoteA2aAgent (researcher)   → port 8001
│   ├── RemoteA2aAgent (judge)        → port 8002
│   └── EscalationChecker
└── RemoteA2aAgent (content_builder)  → port 8003
✅
The entire complex multi-agent pipeline is composed from simple, readable Python. Each agent is independently testable and the composition is declarative.

Deploy to Cloud Run

15 minutes

Deploy each agent as an independent Cloud Run service. Sub-agents deploy first, then the Orchestrator receives their URLs as environment variables, and finally the frontend app.

Step 1: Deploy the Researcher

gcloud run deploy researcher \
      --source agents/researcher/ \

      --allow-unauthenticated \
      --labels dev-tutorial=prod-ready-1 \
      --set-env-vars GOOGLE_CLOUD_PROJECT=$GOOGLE_CLOUD_PROJECT \
      --set-env-vars GOOGLE_GENAI_USE_VERTEXAI="true"

Step 2: Deploy the Judge

gcloud run deploy judge \
      --source agents/judge/ \
      --region us-west1 \
      --allow-unauthenticated \
      --labels dev-tutorial=prod-ready-1 \

      --set-env-vars GOOGLE_GENAI_USE_VERTEXAI="true"

Step 3: Deploy the Content Builder

gcloud run deploy content-builder \
      --source agents/content_builder/ \
      --region us-west1 \
      --allow-unauthenticated \

gcloud run deploy course-creator \
        --source app \
        --region us-west1 \

Summary & Next Steps

🎉
Congratulations! You've built and deployed a production-ready multi-agent system using the Agent Development Kit.

What You Built

  • A Researcher agent with Google Search capability
  • A Judge agent with structured Pydantic output for quality control
  • A Content Builder agent for course creation
  • An Orchestrator using A2A protocol to connect distributed agents

Key Architectural Principles

  • Decomposition: Smaller, focused agents are easier to build and maintain

  • Structured contracts: Pydantic schemas ensure reliable inter-agent communication
  • Distributed deployment: A2A protocol enables true microservice architecture
